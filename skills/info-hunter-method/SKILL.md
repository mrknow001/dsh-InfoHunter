# 暴露面收集 · 层内手法

**判据不在这里。** 什么算证据、三类判定（fact / suspect / infer）、什么该标可疑、收尾要说什么，
都在常驻章程里。这里只放"真做这一层时怎么下手"。

边做边记（`expose_record`），不要等一层做完。

## 通用

**泛解析基线：必须在爆破之前做。** 随机生成 5–10 个高熵子域解析一次；全部指向同一 IP / 同一 CNAME
就说明你测的是通配符，这批「发现」作废。把「已排除，随机样本 8 个全部 NXDOMAIN」写进 `detail`。

**三级验证**：跟基线比 → 排除同模板变体（同一 IP 上一堆「同一个 404 页 + 同一个 Server 头」）→
只有拿到**不同于兜底**的内容，才算确认。

## L1 主域名

- 备案、WHOIS（**注册邮箱**是找其它根域最有效的线索）、工商/官网/招聘/公众号/应用商店开发者账号。
- 反向线索：证书 SAN、同 IP 相邻域、同 CNAME 后缀、MX 指向同一邮件服务商。
- 产出：根域清单 + 每个根域的归属依据。

## L2 子域名

**被动优先，主动在后。**

- CT 日志：全量历史证书里的 DNS 名。**通配证书只说明「有这个后缀」**，必须逐条 DNS 验证。
- 空间测绘：按 `domain=` 或 `cert=` 查。不同平台索引源不同，**多平台交叉能显著提高覆盖**。
- 历史快照：`web.archive.org` 的 CDX 接口能列出归档过的 URL，从中提取主机名是最便宜的一招。
- 字典**自生成**：把已见子域切 token 归纳规则（`api-gw` / `api-v2` → `{api,gw}-{v1..v9,internal,test}`），
  再叠环境词（dev/test/uat/stg/pre/sit/qa）、角色词（api/gw/admin/manage/jenkins/gitlab/grafana/kibana/
  nexus/harbor/ops/monitor）、地域词（bj/sh/gz/sz/hk/us）。组合控制在几千内，并发 ≤ 10。
- DNS 区域传送（AXFR）：几乎总失败，但成本极低，对每个 NS 试一次。

## L3 DNS

- A / AAAA / CNAME / MX / TXT / NS / SOA / SRV，CNAME 链跟到底。
- TXT 常泄：SPF 的 `include:`（邮件服务商）、`_dmarc`、各类 SaaS 校验串、域名验证记录。
- **解析到 `10.x` / `192.168.x` / `127.0.0.1` 是内部域名外泄** —— 高价值线索，不是「解析失败」，照实记。

## L4 端口

- 常见端口：21/22/23/25/53/80/110/143/443/445/993/995/1433/1521/3306/3389/5432/5900/6379/
  8080/8443/9000/9200/11211/27017。先这批，再按资产价值决定是否全端口。
- `open` / `open|filtered` / `closed` / `filtered` 原样记。**端口开放 ≠ 服务可用。**
- UDP 只挑 53/123/161/500/1900，且结果本身不可靠。

## L5 服务

- 识别顺序：banner > 协议握手特征 > TLS 握手（SNI/ALPN/证书）> 特定请求的响应形状。
- **版本号是推断不是事实**，标注来源。
- 无认证的 Redis / MongoDB / Elasticsearch / Memcached / Docker API 是极高价值发现：
  拿到「无需认证即可访问」这一条事实就停（一个 `PING` / `_cat/indices` / `INFO`）。
  **绝不写、绝不删、绝不遍历数据** —— 这条底线在章程「边界」里。

## L6 Web

- 跳转链：几跳、最终落到哪个域名、是否 http→https。
- 路径按性价比：`robots.txt`（`Disallow` 就是作者主动给你的路径清单）> `sitemap.xml` >
  `/.git/HEAD` > `/actuator` > `/swagger-ui.html`、`/api-docs` > `/server-status` > 备份后缀。
  **只 HEAD/GET。**
- 默认页 / 停放页 / WAF 拦截页怎么认，见下面的速查表。

## L7 指纹

可靠性排序（左高右低）：独有静态资源路径 > 响应头组合 > Cookie 名与结构 > 报错页特征 >
HTML 结构 / meta > `__NEXT_DATA__` / `window.__NUXT__` / `data-reactroot` 等运行时标记 >
JS 文件名与 chunk 命名 > favicon hash > 纯版本号字符串命中（最低，最易误报）。

## L8 CDN / 云 WAF 归属

- CNAME 后缀、特征头（`X-Cache`、`CF-Ray`、`X-Amz-Cf-Id`）、多地解析差异、ASN 归属。
- 证书的签发者与 SAN 能区分「边缘证书」和「源站真证书」。
- 找源站是下游的事，这里只记判断依据。**判定结果要落成一条指纹写进 `tech`**，不要只写在备注里。

## 假结果速查

| 陷阱 | 症状 | 做法 |
| --- | --- | --- |
| 泛解析 | 任意随机子域都「存在」 | 先建基线；污染批次整体作废 |
| CDN 回源 | 同一 CDN IP 上几十个域名 | 标 CDN 前置，不当多个独立源站 |
| WAF 拦截页 | 所有路径都返回同样的 403 | 标「探测被拦截」，不记作「路径存在」 |
| 通配证书 | 一个 `*.example.com` 就推几十个主机 | 逐条 DNS 验证，通配本身不算资产 |
| 停放 / 待售页 | 域名可出售、满是广告 | 记 kind=`other`、verdict=`suspect` |
| 默认欢迎页 | nginx / IIS / Tomcat 默认页 | 记线索，不是业务系统 |
| 蜜罐 | 响应过于「完美」、端口全开 | 标 `suspect`，**不要深入交互** |
