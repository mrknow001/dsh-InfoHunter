## 0. 一句话

> 主会话是**唯一写者与决策者**；子代理是**纯函数**（进目标、出结构化事实）；
> 状态全部外置到库，每一轮从库重建，而不是从对话记忆里重建。

## 1. 目标 / 非目标

**目标**：持续、不重复、不丢、可复核、可并行地完成用户的暴露面收集需求。

**非目标**

- 不做 ARTEX 那种 7 种节点 / 5 种边的探索图（我们没有"意图队列 + 多 worker 抢活"）；
- 不做漏洞利用、不做 MITM 留痕、不做审批门；
- 不设授权/范围校验层（既定前提：只收集资产，不做攻击）。

## 2. 设计原则

1. **能在代码里判的，不问模型**：身份键、合并、覆盖度、去重全部程序算。
2. **模型只交原料**：`host/port/url/status/title/...`，永远不交 `key`、`parentKey`、`incomplete` 这类派生值。
3. **状态外置**：计划、任务、负结果、产物都在库里；会话只是执行体。
4. **唯一写者**：只有主会话说"落库"；子代理返回结构化结果，不碰存储。
5. **不写等于没发生**：每步必须落库；收尾有硬门槛。

## 3. 架构

```
主会话（唯一写者 / 决策者）
  读状态   expose_state → plan · coverage · 缺口 · 未决问题 · 最近产物
  决策     选阶段 → 切分任务 → 派子代理（或自己做）
  收结果   结构化 facts/artifacts → 落库（记录/资产/产物）
  更新     plan 阶段推进 · tasks 状态 · 覆盖度

子代理（纯函数，每个只做一件事）
  输入   目标 + 约束 + 只给它需要的工具 + 返回 schema
  输出   有界结构化 JSON；不写库；不做跨步推理
```

## 4. 数据模型增量

| 表 | 用途 | 关键字段 |
|---|---|---|
| `plans` | 计划与边界（按会话） | `scope{targets[], constraints[{type:allow\|deny, text}]}`、`stages[{id,label,state,tool,expected[]}]`、`updatedAt` |
| `tasks` | 小额版 intent：派活 / 去重 / 互斥 / 负结果 | `session, target, layer, tool, state(open/running/done/failed/skipped), owner, startedAt, endedAt, result, error` |

- 覆盖度**不建表**：从 `tasks` + `assets` 派生。
- 约束必须**自包含**：写"只测 abc.example.net"，不写"只测当前目标"（脱离上下文后指代词失效）。

### 4.1 已砍掉的两个字段

| 字段 | 砍掉的理由 |
|---|---|
| `rootDomain` | 主要价值是范围判定，而范围校验层已取消；分组用现成的 `target` 字段就够；判公共后缀（`com.cn`/`co.uk`）还会把别人的域名误归进来 |
| `parentKey` | 运行时已经算过（关联面板的「同 host 端口」就是 `host` 相同节点），存下来只省一次内存遍历 |

### 4.2 独立排期（不在本计划内）

`cSeg`（IPv4 `/24`、IPv6 `/64`）：把"同 IP"扩展成"同网段"，属于**关联能力扩展**，与计划/覆盖度/子代理是两条线。有价值，但不在本轮。

## 5. `kind` 的定位（澄清）

**`kind` 是采集记录的字段，不是资产的字段。** 它只回答"这次观测是关于什么的"，只用于「采集记录」的分类与筛选。

```
一条条记录（有 kind，过程流水）
        ↓ 按 host:port / URL 合并，字段取并集
一张资产表（没有 kind，只有字段）
```

它现在被当成三样东西用，这是混乱来源：

| 职责 | 现状 | 处理 |
|---|---|---|
| ① 记录分类 | 14 个值，用于采集记录筛选 | **保留**，收敛到 6 个 |
| ② 必填规则 | `web` 必须有端口… | **摘掉**：规则改为按字段判（见 §6） |
| ③ 能力声明 | 配置页工具"用途"、测绘"能出什么" | **摘掉**：能力声明只留"形态"（shapes） |

收敛后：`domain`（主域/子域/DNS/测绘域名）、`endpoint`（端口/服务）、`web`（Web/指纹/CDN）、`system`（系统入口/URL）、`cert`、`other`（截图等）。

## 6. 记录硬规则（按字段，不按 kind）

1. **端口**：记录只要带 `protocol` / `status` / `service` / `port` 中**任一**，就必须带端口；`:80` / `:443` 也不省略。
2. **端口可空**：纯域名级观测（子域枚举、DNS、证书）允许无端口。
3. **汇总行拒收**：`asset` 命中「总览 / 汇总 / 清单 / summary / overview」→ 拒收，提示写进 `detail`。
4. **必填缺失 → 拒收**，回执指出"第几条 / 缺什么 / 应该写成什么"；软字段（`ip`/`title`/`tech`/`headers`/`body`）缺失 → 落库并标 `incomplete`。
5. **派生规则**：根路径 Web 资产只在 `port > 0` 时派生。

## 7. 子代理契约

**返回（有界、结构化）**

```
{ taskId, target, ok, summary,
  facts:     [{ kind, host, port, ip, protocol, status, title, tech, headers, body, ... }],
  artifacts: [{ kind, title, content, howFound }],
  negative:  [{ what, why }],     // 试过不行，必须回 —— "不重复"的另一半
  errors:    [...] }
```

**派 / 不派**

| 适合派子代理 | 主会话自己做 |
|---|---|
| 大输出、可独立、可结构化、失败可忽略 | 需要跨步推理（系统判定、内容页判定） |
| 端口扫描、子域枚举、目录爆破、批量指纹、批量截图 | 合并判定、计划推进、收尾汇总 |

**并行切分**：按"互不依赖"切（不同 host / 不同数据源），**不按工具切**；同一 host 的「端口 → 服务 → Web → 指纹」是依赖链，串行。并发上限 3–5，可配。

**去重与互斥**

- 派前查 `tasks`：同 `(target, layer, tool)` 已 done/running 就不派；
- 主会话唯一写者 → 天然互斥，无需 claim；
- 失败写 `failed + error`，`negative` 落负结果，避免重复尝试。

## 8. 提示词结构

- **`[A]` 章程**（可编辑正文）：心法 / 循环 / 记录纪律 / 收尾；
- **`[B]` 能力清单**（运行时）：强制第一步 `expose_config`，回执升级为"有什么能力 + 吃什么/出什么 + 缺什么"；
- **`[C]` 输出规约**（代码固定）：字段字典 + 硬规则 + 面板字段映射 + 自检口径。

**五问**（每步一行）：我有哪些工具 · 这步做什么 · 预期抽哪些字段 · 用户要看到什么 · 我能补什么。

**循环**：`expose_state → 选缺口/阶段 → 声明抽取 → 派活或自做 → 落库 → 再 expose_state`。

**收尾**：`expose_check` 清零或逐条说明 → `expose_question_list` 处理 → 汇总。

## 9. 覆盖度口径

按「资产 × 层」，不按 ARTEX 的资产类型计数：

| 层 | 判据 |
|---|---|
| 解析 | `ip` 或 `cname` 非空，或存在 dns 记录 |
| 端口 | `port > 0` 且有端口观测 |
| 服务 | `service` / `version` 非空 |
| Web | `status` / `title` 非空，或存在 web 记录 |
| 指纹 | `tech` 非空 |
| 系统 | 存在 app 节点或 `basePath` |
| 产物 | 有产物锚到该资产 |

返回：每层覆盖数/百分比 + 未覆盖端点清单（≤50，按缺失层数降序），并保留 ARTEX 的自描述格式（`未覆盖 12（共 87）`）。

## 10. UI 改动

1. 关联区 IP / 端口 chip：**点击复制**，不跳转、不筛选；
2. 主机资产：有端口必显示 `host:port`（含 80/443）；
3. 关联去重：端点与其根路径 Web 资产不再重复出现成两条同样的 chip；
4. 卡片角标：`缺端口`（web 且 `port=0`）、`缺 IP`（`port>0` 且 `ip` 空）；
5. 资产清单顶部：**阶段进度 + 覆盖率条**，点开看缺口清单。

## 11. 分阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 前置验证** | 子代理能否调用我们配置的工具、能否带会话上下文 | 最小实验：派一个子代理跑一个已配置工具，拿到结构化返回 |
| **P1 规则与 kind** | 按字段的端口规则、汇总行拒收、必填拒收、派生规则；`kind` 收敛 6 类；配置页"用途 / 形态"解耦 | 缺端口被拒且给出修正写法；汇总行被拒；纯 DNS 记录可无端口；kind 只剩 6 个 |
| **P2 状态与流程** | `plans` + `tasks` + `expose_state` + 五问/循环/收尾 | 新会话先 `expose_config` → `expose_state`；阶段可推进；收尾顺序正确 |

| **P4 覆盖度与面板** | 覆盖率、缺口清单、计划进度条 | 覆盖率随阶段推进上升；缺口可点开 |

## 12. 风险与前置

1. **子代理能力边界未知（最关键）**：若子代理无法调用用户配置的工具，P3 需改为"主会话串行 + 子代理只做分析"，并行收益消失。
2. **子代理无全局视野**：系统判定、内容页判定必须在主会话。
3. **成本与限流**：子代理并发过高会被限流，需可配上限。
4. **写入纪律**：状态外置后，不写 = 没发生；P2 的收尾门槛必须硬。

## 13. 已决策 / 待确认

**已决策**

- `kind` 只做记录分型，收敛 14 → 6；规则改按字段判；能力声明只留形态；
- `rootDomain` / `parentKey` 不做；`cSeg` 独立排期；
- 主会话唯一写者，子代理纯函数；
- 端口显式（80/443 不省略）；汇总行拒收；根路径 Web 资产仅 `port>0` 派生。

**待确认**

1. 覆盖度用"资产 × 7 层"是否够（还是要更细的字段粒度）；
2. 是否强制每轮 `expose_state`（做不到预注入，只能靠章程 + 面板可见性约束）；
3. 子代理并发上限默认值（3 还是 5）。
