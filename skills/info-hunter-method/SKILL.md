# 互联网暴露面收集 · 分层方法论

本技能是收集分层与判断标准的展开说明。**边做边记**（`expose_record`，一次调用同时进「采集记录」与「资产清单」）：
每完成一小批就写，不要等一层做完。

---

## 通用纪律

**泛解析检测：必须做，且必须在字典爆破之前做。**
随机生成 5–10 个高熵子域（`xk3j9f2.example.com`）解析一次。如果它们全部返回同一个 IP /
同一个 CNAME，那么这一批「子域发现」全部作废 —— 你测的是通配符，不是资产。
把这件事写进 `detail`（「泛解析已排除，随机样本 8 个全部 NXDOMAIN」），它决定这批结果的 `confidence`。

**三级验证：**
- 一级 —— 与基线比（随机子域的响应形状）。
- 二级 —— 排除同模板变体（同一 IP 上一堆「同一个 404 页 + 同一个 Server 头」的域名，往往是同一虚机的兜底）。
- 三级 —— 只有拿到**不同于兜底**的内容，才算确认。

**400 / 403 ≠ 不存在。** 只有 404 和连接失败才是「没有」。状态码原样写进 `detail`。

**置信度锚点：**
- 90–100：直接观测且已排除兜底（自己发请求/自己解析，拿到独有内容）。
- 70–89：直接观测但未排除兜底，或单一来源的被动数据。
- 40–69：推断（CNAME 指向 CDN 所以「应该是托管」；证书 SAN 里出现同组织域名）。
- 0–39：线索级（搜索片段、他人报告、历史快照）。

## L1 主域名

目的：把「一个域名」扩成「一组根域 + 组织归属」。

- 备案、WHOIS（注册人/邮箱/注册商/创建时间）。注册邮箱是后续找**其它根域**的关键线索。
- 企业信息（工商、官网、招聘、公众号、应用商店开发者账号）—— 同一主体往往有多个根域。
- 反向线索：证书 SAN、同 IP 相邻域、同 CNAME 后缀、MX 指向同一邮件服务商。
- 从资产反推：响应头、页面版权、JS 里的公司标识。

产出：根域清单 + 每个根域的归属依据。**多个根域时先跟用户确认哪些在授权范围内。**

## L2 子域名

顺序：**被动优先，主动在后**。

被动（不接触目标）：
- 证书透明日志（CT）：全量历史证书里的 DNS 名。**注意通配证书** —— 它只说明「有这个后缀」，
  不代表具体主机存在，必须逐条 DNS 验证。
- 空间测绘平台：按 `domain=` 或 `cert=` 查。不同平台索引源不同，**多平台交叉能显著提高覆盖**。
- 公开情报 / 搜索引擎：`site:`、`inurl:`、代码托管平台搜域名、历史快照
  （web.archive.org 的 CDX 接口能列出归档过的 URL，从中提取主机名是最便宜的一招）。

主动（接触目标，控速）：
- 字典爆破：**字典要自生成**，从已有子域归纳命名规则再套组合。
- DNS 区域传送（AXFR）：几乎总是失败，但成本极低，对每个 NS 试一次。
- 虚拟主机枚举：只对已确认 IP 做，且**必须**有基线比对。

**命名规则归纳**（比字典更重要）：把已发现的子域切 token 观察规律。
例如已见 `api-gw.example.com`、`api-v2.example.com` → 规则 `{api,gw}-{v1..v9,internal,test,uat,dev,stg}`。
再叠加环境词（dev/test/uat/stg/pre/sit/qa）、角色词（api/gw/admin/manage/ops/monitor/jenkins/
gitlab/grafana/kibana/nexus/harbor）、地域词（bj/sh/gz/sz/hk/us）。组合控制在几千以内，并发 ≤ 10。

## L3 DNS

- A / AAAA / CNAME / MX / TXT / NS / SOA / SRV。CNAME 链跟到底。
- TXT 经常泄露东西：SPF（`include:` 里是邮件服务商）、域名验证记录、`_dmarc`、各类 SaaS 校验串。
- 判断真资产还是停放/泛解析：对照 L1 的泛解析基线。
- **内网泄露**：有些子域解析到 `10.x` / `192.168.x` / `127.0.0.1` —— 这是内部域名外泄，
  是高价值线索（不是「解析失败」），照实记，置信度高。

## L4 端口

- 先常见端口（21/22/23/25/53/80/110/143/443/445/993/995/1433/1521/3306/3389/5432/5900/6379/
  8080/8443/9000/9200/11211/27017），再决定是否全端口。
- **控速是硬要求**：不做全端口压测，并发不拉满；对生产资产尤其保守。
- 端口开放 ≠ 服务可用。区分 `open` / `open|filtered` / `closed` / `filtered`，原样记录。
- UDP 只挑有意义的（53/123/161/500/1900），且 UDP 结果本身不可靠。

## L5 服务

- 协议识别：banner、协议握手特征、TLS 握手（SNI/ALPN/证书）、特定请求的响应形状。
- 版本：banner 版本号、报错页、特定路径差异。**版本号是推断不是事实**，标注来源。
- 明文协议（Redis/MongoDB/Elasticsearch/Memcached/Docker API）若**无认证**，是极重要发现 ——
  但**只做只读确认**（一个 PING / 一个 `_cat/indices` / 一个 INFO），**绝不写、绝不删、绝不遍历数据**。
  拿到「无需认证即可访问」这一条事实就停。
- 数据库/管理端口暴露：记下来交给下游，本阶段不深入。

## L6 Web

- 协议与跳转链：http 是否 301 到 https；几跳；最终落到哪个域名（**落到授权外要标注**）。
- 状态码、标题、Content-Type、Content-Length、Server / X-Powered-By / Via / X-Cache。
- 默认页 / 停放页 / WAF 拦截页识别（三类假结果的主要来源）：
  - 停放页：注册商模板、大量广告、「此域名可出售」。
  - 默认页：IIS / nginx / Apache / Tomcat / 各框架欢迎页 —— 只说明「装了但没配」。
  - WAF 拦截页：统一指纹（特定 cookie、特定状态码 + 特定 body 长度）。**被拦下不代表资产不存在，
    但要标注「探测被拦截」**，不要记成「Web 资产已确认」。
- 常见路径：`robots.txt`（最便宜且最有效）、`sitemap.xml`、`/.git/HEAD`、`/actuator`、
  `/swagger-ui.html`、`/api-docs`、`/.well-known/security.txt`、`/server-status`、备份后缀。
  **只 HEAD/GET。** `robots.txt` 的 `Disallow` 是作者主动告诉你的路径清单，高价值。

## L7 指纹

来源按可靠性排序：独有静态资源路径 > 响应头组合 > Cookie 名与结构 > 报错页特征 >
HTML 结构/meta > `__NEXT_DATA__` / `window.__NUXT__` / `data-reactroot` 等运行时标记 >
JS 文件名与 chunk 命名 > favicon hash > 纯版本号字符串命中（最低，易误报）。

**只记两类东西**：组件 + 版本 + 证据；以及由指纹推出的攻击面方向。
**不要在本阶段验证漏洞。**

## L8 CDN / WAF 归属

- 判断直连还是前置：CNAME 后缀、CDN 特征头（`X-Cache`、`CF-Ray`、`X-Amz-Cf-Id`）、
  多地解析差异、ASN 归属。
- TLS 证书的签发者与 SAN 能区分「边缘证书」还是「源站真证书」。
- 找真实源站是下游的事；本阶段只记录**判断依据**。
- 云厂商归属决定后续规则边界（云 WAF、安全组）。

## 七类最常见的假结果

| 陷阱 | 症状 | 正确做法 |
| --- | --- | --- |
| **泛解析** | 任意随机子域都「存在」 | 先做泛解析基线，污染批次整体作废 |
| **CDN 回源** | 同一 CDN IP 上几十个域名 | 标注 CDN 前置，不当作多个独立源站 |
| **WAF 拦截页** | 所有路径都返回同样的 403 | 标注「探测被拦截」，不记作「路径存在」 |
| **通配证书** | CT 里一个 `*.example.com` 就推几十个主机 | 逐条 DNS 验证，通配本身不算资产 |
| **停放 / 待售页** | 域名可出售、满是广告 | 记为 `other` 并标低置信度 |
| **默认欢迎页** | nginx/IIS/Tomcat 默认页 | 记为线索，不是业务系统 |
| **蜜罐** | 响应过于「完美」、端口全开 | 标注怀疑，降低置信度，**不要深入交互** |

## 收尾清单

给用户的汇总至少回答：

1. 覆盖了哪几层？每层多少条？
2. 哪几层**缺**，为什么缺（没工具 / 被 WAF 拦 / 未授权 / 时间不够）？
3. 有哪些高价值线索值得进下一阶段（无认证服务、内网域名外泄、管理后台、API 文档暴露）？
4. 有哪些待用户确认的边界问题（范围外资产、是否加入授权）？

不要在汇总里复述全部条目 —— 它们在面板里。
